# mand-mobile 3.0 多框架改造计划（TDD 驱动）

## 总体架构

将现有 Vue 2 单包仓库演进为 pnpm monorepo，v3 发版：

```
mand-mobile/
├── packages/
│   ├── core/        @mand-mobile/core      框架无关 TS 逻辑层（主入口严格 DOM-free）
│   │                @mand-mobile/core/web  DOM 专属模块子入口（dom/render/scroller）
│   ├── styles/      @mand-mobile/styles    设计 token + 组件样式（编译产物为纯 CSS）
│   ├── vue/         mand-mobile@3          Vue 3 版（保留原包名，主版本号升 3）
│   └── react/       @mand-mobile/react     React 版（peer: react >= 18）
├── docs/            文档站（Astro + Starlight）
├── legacy/          现有 v2 代码冻结归档（移植参考，不参与构建）
└── （后期）packages/react-native/、packages/weapp 或 taro/
```

**多渲染层共享**：core（DOM-free 主入口 + /web 子入口）、styles（stylus 源 → CSS/rpx 多产物）、`md-*` 标记结构约定（React 复用同一份 CSS；小程序 WXML 沿用同类名）。

## 质量保障与 TDD 工作流（贯穿所有里程碑）

**每组件/模块统一 Red-Green-Refactor 循环**：
1. Red：从 v2 spec + README/demo 提取行为清单 → 先写测试（VTU v2 / RTL）+ golden HTML 对比用例，确认失败
2. Green：迁移/实现组件至全绿
3. Refactor：绿灯保护下重构（逻辑下沉 core）
4. Gate：CI 门禁通过才可合并

**四层测试金字塔与覆盖率门禁**：
- L1 core 纯逻辑单测（TDD 主战场）——行/分支 ≥ 90%
- L2 组件功能测试（双端）——行/分支 ≥ 80%，per-component 覆盖率报告，vite coverage + istanbul provider 阈值即失败
- L3 golden HTML 结构对比（v2→v3 迁移契约 + Vue↔React 一致性）——全过或显式白名单
- L4 Playwright 视觉回归——双框架同场景截图比对 + 基线比对，0.1% 像素容差，基线变更须随 PR 显式提交

**CI 流水线**：lint → L1/L2（coverage 阈值硬门禁）→ L3 golden → 构建 → L4 视觉回归。分支保护 + PR 模板勾选"行为清单已提取、测试先行、覆盖率达标"。

**测试基建**：vitest.workspace 三项目（core=node、vue=jsdom+VTU v2、react=jsdom+RTL+IS_REACT_ACT_ENVIRONMENT），`pnpm test` 全跑；golden 工程依赖已发布 mand-mobile@2.7.0 + vue@2.7 渲染 demo 场景产出规范化 HTML 基线。

## 关键技术决策

- **Vue 3**：`<script setup>` + TS；`modelValue`/`update:modelValue`；mixins→composables；命令式 API 用 `render()` 重写工厂
- **React**：FC + hooks（DOM-light，为 Taro 留门）；`createRoot()` 命令式工厂；自写 useCssTransition 复用 CSS 动画
- **构建**：pnpm + TS 5 + Vite lib mode（esm/cjs + d.ts）；stylus + postcss（pxtorem 默认 + vw 变体 + 预留 px→rpx）；per-component 入口 + sideEffects 按需加载
- **文档站**：Astro + Starlight 双集成 islands，框架 Tab + client:visible 懒水合；中英双语 + Pagefind；starlight-typedoc 生成 API 表
- **版本**：changesets；mand-mobile@3.x、@mand-mobile/react@0.x
- **v2 处置**：归档至 legacy/（发 3.0 前删除），v2 线仅安全修复
- **Node >= 20**，ESLint 9 flat + Prettier

## 首批组件范围（~24 个，双框架同步 TDD 交付，v2 均有 spec/demo 来源）

- 基础：Button、Icon、Tag、Amount、CellItem、Skeleton、NoticeBar、ActivityIndicator、Progress
- 弹层反馈：Popup、Toast、Dialog、ActionSheet、Tip（含命令式 JS API）
- 表单：Field、InputItem、Switch、Stepper、NumberKeyboard、Codebox、Agree、Check 系列、Radio 系列
- 选择器（首批收尾）：Picker、DatePicker

## 里程碑

**M1 仓库现代化 + 测试基建先行**：pnpm monorepo 骨架、TS/ESLint/Vitest workspace、coverage 阈值配置、Playwright 基建、changesets、CI 流水线（含门禁与分支保护）、v2 冻结至 legacy/
**M2 core + styles 包（TDD 主战场）**：core 先写测试（从 v2 spec 提取逻辑断言，red）再迁移实现（green），90% 门禁；styles 抽取 .styl + 编译流水线，与 v2 产物 CSS diff 验证；golden 工程产出首批基线
**M3 Vue 3 包**：包基建 + 首批组件逐个走 Red-Green-Refactor（交付 = 行为清单全断言 + golden 对比通过/白名单 + 80% 覆盖率）+ playground
**M4 React 包**：包基建（createRoot 工厂、useCssTransition，测试先行）+ 同批组件同流程 + L4 双端视觉比对 + playground
**M5 文档与发布**：Astro + Starlight 文档站；changesets 发布 3.0.0-beta
**M6 长尾组件**：ScrollView/Swiper/Slider（core scroller，单测最重的部分）、Tabs/TabBar/DropMenu/Selector/Steps/Landscape/ImageViewer、Chart/Ruler/ImageReader/LicensePlate/Captcha/Cashier/Bill/ResultPage/WaterMark 按需排期，同 TDD 流程
**M7 React Native 包**：token→TS 主题 + StyleSheet；core 主入口复用；gesture-handler + reanimated；原生滚动替代 scroller；高频子集 ~15 个 + RN playground；测试用 RN Testing Library
**M8 小程序包**：原生微信（@mand-mobile/weapp）或 Taro 编译型（多端覆盖，复用 React hooks）；样式 rpx 变体 + hover-class 改造；原生 scroll-view/swiper；测试用 miniprogram-simulate 或 Taro 工具

## 主要风险与对策

- 全量 60 组件周期长 → 分期 + 长尾按需排期，legacy/ 随时对照
- 覆盖率凑数风险 → 行+分支双指标、行为清单人工 review 项
- 视觉回归环境抖动 → 0.1% 像素容差 + 人工审定基线变更
- stylus 维护度低 → 仅编译源，产物纯 CSS；后续可迁 CSS-first
- 两端标记漂移 → L3 golden 对比 CI 门禁
- scroller 触摸模型偏老 → core/web 迁移时现代化
- 多端渲染层差异 → 接受"渲染层各自实现，逻辑与样式源共享"边界

## 批准后先执行的范围

M1 + M2（monorepo 与测试门禁基建、core TDD 迁移 + 90% 覆盖、styles 流水线、golden 基线产出），作为第一个可交付阶段；M3 起按里程碑推进。
